# 功能分类、接收排列与 CPU/CUDA 计时（更新至 0.16）

2026-10-29新增[二维CPU32线程／GPU性能模式FP32/FP64四档性能实测](PERFORMANCE_PRECISION_2D.md)：包含弹性及GSLS+CFS-PML、5次重复、实际功耗/频率/利用率、内存预检与原始数据。二维当前性能比较以该报告为准；历史三维及界面计时说明保留原口径。

## 控制面板分类

0.10 起，顶部固定横向显示“建模、采集、运行、显示、导出”五个入口，替代此前“功能分类”下拉菜单；下方只显示本类相关页签，各组可展开/折叠：

| 分类 | 页签与内容 |
|---|---|
| 建模设置 | 模型：尺寸、地形；介质：均匀/分层材料和地层表 |
| 震源与采集 | 震源：位置、主频；接收排列：几何、深度、采样与定位 |
| 运行与性能 | 运行：推进、停止条件、每帧预算；性能对比：计算核心、耗时、历史比较 |
| 显示 | 分量、色带、增益、网格、相机/布局、主题与字号 |
| 导出 | 原始 VTS、Vz 或三分量接收 CSV |

参数仍在“应用修改并重建”后生效。计算核心从“运行与性能 → 性能对比 → 计算后端”设置，重建后从零开始；失败时保留旧会话。当前默认模拟时长 1 s、最大计算步数 5000，默认优先使用可用 CUDA。

## 接收排列

0.16 起界面明确显示每方向几何容量和面阵耦合上限，新增显式道数适配。起点 s、节点数 N、间隔 d 对应的位置数上限为 `1+floor((N−1−s)/d)`。另一方向道数 n 固定时，面阵当前方向还受 `floor(1024/n)` 限制。道数是位置数，不是间隔数；1024 是总位置预算，三分量另存。−1 表示起点居中，不代表整条排列居中。单线不使用另一方向的间隔/道数，其预览横向间距显示为 0。

使用物理网格的零基索引，不包含虚节点。四种模式为：

- 自动 X 测线：X=2..Nx−3，Y=Ny/2，默认 Z=1；保留此前 Nx−4 道的行为。
- 自定义 X 测线：设置起点 X/Y、X 方向道数和间隔节点数、Z 深度。
- 自定义 Y 测线：设置起点 X/Y、Y 方向道数和间隔节点数、Z 深度。
- X-Y 面阵：设置两方向道数、间隔及共同 Z，先沿 X 编号，再沿 Y 编号。

起点 X/Y 为 −1 表示该方向使用模型整数中心。间隔须为正整数；自定义每方向最多 300 个，面阵总数最多 1024。直接输入时程序校验最后一个接收点是否仍在模型内，不会把超界道放到虚节点；输入错误不丢弃旧模型和记录。通过模型预设或容量适配缩小网格时，会同步适配越界起点和道数，待应用后生效。

例如起点 `(2,2)`，X 道数 12、Y 道数 8、两方向间隔 1、Z=1，将生成 96 个接收器。h=10 m 时水平间隔为 10 m。固定 k 深度随曲网格变形，不等于固定物理高程或固定当地埋深。面阵展平为道号显示，相邻的两条 Y 排列在道集里连续编号，不能把整幅道集误读成单条物理直线。

接收三分量在每个有效时间步后同步采样，包含 t=0，采样间隔为当前 dt；推进 n 步有 n+1 个样本。接收模式、道数和位置会改变真实采样及 CUDA 数据回传量，因而影响总计算耗时。界面显示暂存道数/间隔和生效道数；“定位当前接收器”将三切片移到当前选中接收点，视图标记显示实际位置。

## 计时边界与公式

使用 `std::chrono::steady_clock` 在求解器中逐个完整 RK4 步计时，覆盖基础场保存、四阶段更新、自由表面操作、有限性/能量检查及原始接收采样。CUDA 的统计与接收回传会同步设备工作，计时结束时对应步骤已执行完成，不能只测异步 kernel 提交。

只累计成功提交的有效步骤。初始化（几何、分配、CUDA 上传及初始诊断）单独计时；绘图、交互、暂停、VTS/CSV 导出以及帧间空闲不计入推进耗时。不主动扣除第一步的预热代价。失败/被回退的步不计为有效计时步，故障后该运行不宜作为正常性能比较。

设已完成且计时的步数为 n，第 i 个有效步实际耗时为 ti（毫秒）：

\[
T_{compute}=\sum_{i=1}^n t_i/1000,\qquad
\bar t=\sum_{i=1}^n t_i/n.
\]

\[
R_{steps}=n/T_{compute},\qquad
R_{physical}=n\,dt/T_{compute},\qquad
T_{remain}\approx(N-n)\bar t/1000.
\]

界面显示累计秒数、最近/平均每步毫秒、最短/最长步、步/秒、模拟时间与实际耗时比、预计剩余计算时间，以及单列的初始化耗时。模拟时间 `n dt` 与真实计算秒数是不同指标。帧率不再充当计算效率。

单步按钮、快捷键 N、持续运行和命令行批量推进均走同一计时路径。暂停或 `advance(0)` 不增加计时，完成后继续请求推进也不增加计时；成功重建清零本次统计。0.15 的 C 原位清空场和接收记录，同时开始新的推进计时会话，保留原模型的初始化耗时；界面先保存旧计时记录，以便比较重新运行前后的结果。

## 公平比较流程

1. 确定模型几何、材料、震源、CFL、模拟时长、最大步数和接收排列，应用重建。
2. 在“运行与性能 → 性能对比 → 计算后端”选择 CPU，确定 CPU 线程数并重建，再运行到选定步数。
3. 使用同样物理设置选择 CUDA 并重建，运行到完全相同的步数。
4. 打开“性能对比”，查看两次记录和 CPU 总耗时÷CUDA 总耗时；大于 1 表示本次 CUDA 更快。

当前会话的统计会更新到历史记录；切换核心或重建前保留旧记录，内存中最多 16 次，不跨程序重启持久化。只有完整物理参数对象、dt、已完成步数、接收数及计时步数一致且耗时为正，才显示加速比。材料层、源位置/主频、接收配置或停止条件不同均不自动配对。表中 CPU 行附线程数，报告也保留设备名称。

初始化耗时单列，比较公式不把它混入时间步耗时；需要比较短作业的总开销时，可在 CSV 中分别相加初始化与计算秒数。当前为包含诊断/采样的应用计算耗时，不是纯 CUDA kernel 的设备事件计时。显卡/CPU 时钟、温度、后台负载、首次运行及线程设置会影响结果，重要对比宜重复多次并查看分布。

“清空对比记录”清除已保存条目，正在计算的当前条目下次刷新仍会重新加入。CSV 导出位于 `../out/performance_runs.csv`，包含配置标识、完整参数文本、核心、设备、线程数、网格、接收数、步数、dt、模拟时长、计算与初始化秒数及各项速率。配置标识用于阅读和检索，真正配对使用完整参数相等比较，不靠哈希值判断相同。

## 验证记录

当前二维/三维完整回归已通过 19 项 CTest。接收与计时专项覆盖四种排列、96 道面阵、CPU/CUDA 三分量一致、零时刻时间轴、越界防御、有效步计时、重建/清空计时复位、完成/空推进不计时、拒绝步不提交，以及不同配置不能配对比较。1024 道容量、末道非零采样和整数溢出防御见 [最新专项验证](VERIFICATION_0_16.md)。

当前默认 CFL=0.8，旧值 0.22 可输入复现。调整 CFL 改变完成同一物理时长的步数，不减少每个 RK 步的工作；比较时应保持配置与实际 dt 相同。[CFL 标定证据](NUMERICS_AND_VALIDATION.md#cfl-calibration) 保留原条件下的终态场差异与效率解释，不将这类差异当作绝对精度或 CPU/CUDA 加速比。

正式 CPU/CUDA 性能测试采用六档二维/三维模型、32 线程、20 步预热、100 步计时、5 次重复中位数，共 60 轮。图表、倍速曲线、统计波动、计时范围、硬件和原始 CSV 统一见 [性能对比报告](PERFORMANCE_BENCHMARK.md)。不再将早期 GUI 底栏和单轮小模型耗时作为当前性能基准。

`--smoke-acquisition` 在十二组窗口尺寸、字号、中英文、主题和布局下核对功能分类与性能页面，保持原始记录指纹、物理状态、相机和增益；`curvilinear_acquisition_and_timing` 独立检查计时与三分量 CSV 元数据。独立 CSV 解析核对两端配置、dt/步数、累计/平均耗时关系、列数及样本数。GUI 自动断言与正式推进性能测试分开执行。
